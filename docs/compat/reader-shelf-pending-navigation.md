# 保存进度期间的书架换书

固定上游 `fa22f271` 的 `web/src/components/BookShelf.vue:116` 从选中的书构造阅读信息并发出 `changeBook`。父组件 `web/src/views/Reader.vue:913` 当场提示「换书成功」、关闭面板、提交所选书并加载目录。因此一次旧点击没有机会在后来的跨书导航后再次切换书籍。

OpenReader 基线 `87905056` 的 `useReaderShelf.select` 关闭面板后先尽力保存当前进度，再用所选书的进度构造 Reader 路由。PR #5 已处理等待期间目标书成为当前书的情况。若用户离开最初的书又返回，旧选择仍会执行一次跳转。Vue Router 和异步保存是允许的运行时适配；补齐下列时序恢复上游点击只影响当次阅读的行为。

| 场景 | 验收行为 |
| --- | --- |
| A 中选择 B，保存挂起，随后到 C 再回 A | 保存成功或失败后，均保留当前 URL 和正文，不再跳 B，也不显示旧的成功消息。 |
| 离开 Reader 或销毁该实例 | 实例上的待完成保存可自行结束，旧选择不能重新打开阅读器。 |
| 同一本书的进度更新仅替换 query | 选择仍有效；正常切换只提示一次，目标路由按目标书的进度构造。 |
| 重复选择 B，第一次保存先返回 | 延续 PR #5 的约定；首次完成可切书，后续保存不能重设 B 的阅读位置。 |
| 有效的选择遇到保存失败 | 延续尽力保存的语义，正常切书，不丢弃已建立的本地进度。 |

用可控制的保存 Promise 和 Vue Router 验证成功与失败分支，通过真实 Chrome 的书架选书以及浏览器后退、前进验证用户可见结果。此次调整的边界为 Reader 的待处理选书操作。
