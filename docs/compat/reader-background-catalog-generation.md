# 换书后迟到的书籍和目录刷新

固定上游 `fa22f271` 的 `web/src/views/Reader.vue` 中，书架换书调用 `loadCatalog(true, true)`。成功回调把结果设为阅读中的书籍目录，再定位正文。上游在这个回调里读取当时的 readingBook，没有对重复打开同一本书的请求排序。

OpenReader 基线为 `70c8df9e`。Reader 优先使用当前用户和书籍对应的浏览器缓存，在后台向服务端读取书籍和目录。缓存优先支持离线阅读；过滤过期响应属于缓存加固。此处只处理读书期间的书籍详情和目录加载。

| 场景 | 兼容要求与验收 |
| --- | --- |
| A 的后台刷新未完成，切到 B 后又打开 A | 第二次 A 的详情、目录先返回并显示后，第一次 A 的响应不能覆盖当前界面或持久化结果。用可控的响应顺序复现。 |
| 前一次加载还在等待章节正文 | 当它恢复执行时，不能以新书或新一次打开的身份启动后台刷新。 |
| 离线及旧数据 | 继续使用已有的用户范围、缓存键、值格式、IndexedDB 和 localStorage 回退。当前加载的有效响应应正常更新缓存。再次打开页面应看到较新的目录。 |

使用可控响应顺序的单元测试检查请求和缓存提交，真实浏览器经 Reader 书架完成 A→B→A，检查目录标题和缓存。API、数据卷及 SQLite 格式沿用原有约定。

## 回归证据

在真实 Chrome 中运行 `scripts/smoke/reader-aba-catalog-contract.mjs`。先打开 A 预热缓存，通过书架切到 B 后重开 A，挂起这次目录刷新。再经 B 返回 A，让新目录先显示，再放行挂起的响应。

- 基线 `70c8df9e` 的目录和 IndexedDB 都从 `catalog-3-0` 回退到 `catalog-2-0`，断言失败。
- 修复后，1440×900、390×844、360×800 三个视口的页面和 IndexedDB 均保留 `catalog-3-0`。随后模拟目录接口断网，重新加载阅读页仍能打开最新目录。
- 书籍详情请求、离开 Reader、延迟的章节加载，以及 IndexedDB 写入失败后的 localStorage 回退由单元测试覆盖。现有书架切换浏览器回归在上述三个视口分别验证了分页和滚动模式。
