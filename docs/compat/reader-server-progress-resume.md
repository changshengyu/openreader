# 服务端进度恢复的书籍归属

固定上游 `fa22f271` 的 `web/src/views/Reader.vue` 在重新进入阅读器时按 `bookUrl` 区分是否已换书（约第 874 行），并按当前阅读书籍恢复位置、加载目录。OpenReader 支持在先显示本地进度后，用同一本书更新的服务端进度恢复阅读。这个异步步骤属于多端进度同步适配。

在基线 `44a5cde3`，恢复开始时检查了书籍和当前进度，但在等待 Vue Router 替换 URL 和等待章节加载之后，回调仍能继续。内存路由复现中，书 1 的恢复被切到书 3 的导航取消后，旧回调仍要求书 3 加载书 1 的章节索引，并调用已保存标记。

| 验收场景 | 预期 |
| --- | --- |
| 打开 A，先读本地位置，服务端返回更新的位置 | 仍在本次阅读且基线未改变时，恢复 A 的正确章节和偏移；显式位置继续优先。 |
| 恢复导航被取消或中止，或已切书、重开、离开 Reader | 旧回调不得操作当前章节或把新位置标为已保存。 |
| 章节加载期间切书，或章节未成功应用 | 回调结束时不得将别的阅读位置记为已保存。 |
| URL 已经是恢复目标，但正文仍显示较早位置 | 仍需允许恢复当前书的目标正文。 |

用可控 Vue Router 导航验证异步顺序，以真实浏览器核对当前书籍、正文和恢复位置。沿用进度 API、路由参数以及已有的本地、服务端进度格式。

## 实测记录

运行 `scripts/smoke/reader-server-progress-resume.mjs`，通过模拟较慢的进度响应和 Vue Router 导航守卫控制先后顺序。书 3 先显示本地第 10 章，服务端随后要求恢复第 8 章。

- 基线 `44a5cde3` 在换到书 1 后仍执行了书 3 的回调，URL 属于书 1，正文却从第 1 章跳到了第 3 章。
- 初次修正后，普通导航先到达与内部恢复相同的 URL 时，浏览器仍显示第 10 章。修正后的内部替换在路由历史状态上留下本次导航标识，位置监听器只对实际提交的那次替换跳过重复加载。历史项没有标识时仍按普通导航处理。该标识不参与 URL、进度数据或服务端请求。
- 在 1440×900、390×844、360×800 三个视口分别验证正常恢复、换书取消、普通导航抢先到达同一 URL。九组均通过，最后一种场景在旧导航尚未释放时就能看到新正文。

Vue Router 单测补充覆盖同书重开、Reader 销毁、重复、拒绝和重定向导航，以及章节未成功应用时的保存标记。上游恢复位置的书籍缓存键另见 `web/src/views/Reader.vue:2550`。
