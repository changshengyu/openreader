# Browser Smoke Checks

Use this document with `openreader-regression` for UI changes.

## Script

Install the pinned crash-safe headless browser once after `npm install`:

```bash
npm install
npm run smoke:install-browser
```

All scripts use `scripts/smoke/playwright-runtime.mjs`. By default it launches Playwright's
Chromium Headless Shell, not the macOS system Google Chrome application. This avoids GUI app
registration crashes and keeps the user's normal Chrome profile untouched. `CDP_URL` and
`CHROME_PATH` are explicit overrides only.

```bash
TARGET_URL=http://127.0.0.1:8080 node scripts/smoke/openreader-smoke.mjs
```

For a specific reader page:

```bash
TARGET_URL=http://127.0.0.1:8080 \
SMOKE_READER_URL=http://127.0.0.1:8080/books/1/read \
node scripts/smoke/openreader-smoke.mjs
```

For the mocked mobile Reader contract:

```bash
TARGET_URL=http://127.0.0.1:5173 node scripts/smoke/reader-mobile-contract.mjs
```

For the night Element Plus contract (reader-dev `App.vue` `.night-theme`: home workspace dialog,
message box, sidebar select dropdown and the light login page):

```bash
TARGET_URL=http://127.0.0.1:5173 node scripts/smoke/night-element-theme-contract.mjs
```

To compare day computed styles between two builds, both scripts take `SMOKE_DAY_SNAPSHOT=<file>`: each
viewport appends its day snapshot as a JSON line before any night assertion runs.
`reader-mobile-contract.mjs` also accepts `SMOKE_NIGHT_ONLY=1 SMOKE_VIEWPORT=<width>x<height>` to run only
the built-in night segment at one viewport.

The repository tooling package pins the Playwright version used by the shared runtime, independently
from the frontend dependencies copied into Docker. On macOS the browser process
may need to run outside a restricted sandbox so it can register its Mach rendezvous port.

## Service worker

Production builds register the offline-shell service worker (`/sw.js`, generated by `npm run build`)
in secure contexts, and `127.0.0.1` counts as one. A controlling worker would answer precached
`/assets` requests itself, bypassing `page.route` holds and mocks, so the shared runtime creates every
context with `serviceWorkers: 'block'` unless a contract passes `serviceWorkers: 'allow'`. The existing
contracts therefore keep their pre-worker behaviour; Playwright logs a console warning when it blocks a
registration.

`pwa-service-worker-contract.mjs` opts in. It builds the Go server, serves a private copy of
`frontend/dist` and covers registration and precache contents, the offline shell with the server
stopped, account isolation, an A→B release, the version-click update, `?nopwa` and the insecure-context
fallback at all three viewports (contract
`docs/compat/pwa-service-worker-fixed-baseline-second-audit-p2-contract.md`):

```bash
cd frontend && npm run build && cd ..
node scripts/smoke/pwa-service-worker-contract.mjs
```

## Reader failure progress

`reader-failure-progress-contract.mjs` needs a real OpenReader server, not mocks: `PUT /api/progress` must be answered
by the backend, whose chapter identity check (`400 invalid progress payload`) the mocked Reader contracts never see. It
registers a fresh user and imports its own TXT books, so any instance with registration open works; `page.route` only
fails one chapter's content or one book's catalog, holds one chapter's content, or fails `PUT /api/progress`
(contract `docs/compat/reader-failure-progress-payload-fixed-baseline-second-audit-p0-contract.md`):

```bash
TARGET_URL=http://127.0.0.1:8080 node scripts/smoke/reader-failure-progress-contract.mjs
```

## Release gate

`.github/workflows/docker-publish.yml` runs `scripts/smoke/release-browser-smoke.sh` right after the
native validation image is built, before the arm64 build and the publish step. The script starts a
fresh container from `openreader-ci:<sha>` (no volumes, Docker-assigned loopback port) and runs
`openreader-smoke.mjs` in the pinned headless shell: a page error, console error, `/api/` 5xx or empty
`#app` at any of the three viewports fails the release. `release-browser-smoke.test.mjs` checks the
workflow wiring and the checker's failure handling on owned pages.

Images are not built locally. To check a local frontend build in the release runtime, serve it
through a published image:

```bash
docker pull ghcr.io/changshengyu/openreader:latest
IMAGE=ghcr.io/changshengyu/openreader:latest SMOKE_PUBLIC_DIR=frontend/dist ./scripts/smoke/release-browser-smoke.sh
```

## Required manual/automated coverage for reader work

- Desktop: `1440x900`.
- Mobile: `390x844`.
- Mobile: `360x800`.
- Check for blank page, console errors, and failed core API requests.
- For reader mobile, verify default tool layer, panel coexistence, center tap behavior, and symmetric content padding.
